Аудит кода 

Проанализировав код вашего проекта (Amnezia Web Panel), я выявил ряд проблем безопасности и работоспособности, которые требуют внимания. Вот моя рецензия:

🔴 КРИТИЧЕСКИЕ ПРОБЛЕМЫ БЕЗОПАСНОСТИ
1. Уязвимость к SQL-инъекциям через f-string
Файл: /workspace/routers/settings.py (строки 123, 141, 155, 169)
python
1
Хотя это не прямые SQL-запросы, использование f-strings с пользовательским input в logging может привести к log injection атакам. Переменная provider приходит из URL path parameter и не валидируется должным образом перед логированием.
2. Небезопасная обработка исключений с утечкой информации
Файлы: Практически все router'ы
python
123
Возврат str(e) клиенту может раскрыть чувствительную информацию о внутренней структуре приложения, путях к файлам, SQL-запросах и т.д.
3. Отсутствие rate limiting на критических endpoint'ах
Несмотря на наличие slowapi, некоторые endpoint'ы для работы с серверами и протоколами не имеют явных лимитов, что позволяет проводить brute-force атаки.
4. CSRF токен не HttpOnly
Файл: /workspace/middleware.py (строка 94)
python
1
Это делает CSRF-токен доступным для JavaScript, что потенциально позволяет XSS атакам украсть его. Хотя это необходимо для double-submit паттерна, требуется дополнительная защита от XSS.
5. CSP политика слишком разрешающая
Файл: /workspace/middleware.py (строки 36-45)
python
12
'unsafe-inline' для скриптов и стилей значительно снижает защиту от XSS атак.
6. Пароли в логах при исключениях
При использовании logger.exception() с f-strings, чувствительные данные могут попасть в логи.
🟡 ПРОБЛЕМЫ РАБОТОСПОСОБНОСТИ
7. Несоответствие сигнатур функций
Файлы: /workspace/app.py vs /workspace/routers/users.py
python
1234567
Функции ожидают data: dict, но вызываются с db: AsyncSession. Это критическая ошибка которая сломает функционал удаления/блокировки пользователей.
8. Потенциальная race condition при работе с сессиями
Файл: /workspace/routers/auth.py (строка 39)
python
1
Нет атомарности при проверке капчи, возможна гонка условий.
9. Отсутствие валидации входных данных
Многие Pydantic модели используют Optional без строгих ограничений, что позволяет передавать некорректные данные.
10. Hardcoded credentials по умолчанию
Файл: /workspace/config.py (строка 158)
python
1
Пароль secure_password по умолчанию - крайне небезопасно для production.
11. Недостаточное логирование аудита
Отсутствует логирование критических действий (удаление пользователей, изменение прав доступа, экспорт конфигов), что затрудняет расследование инцидентов.
12. Проблемы с управлением секретами
Файл: /workspace/managers/secrets.py
MASTER_KEY должен храниться в secure enclave/HSM для production
Отсутствует ротация ключей шифрования
Нет механизма re-encryption при смене MASTER_KEY
