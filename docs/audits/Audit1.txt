Сводный отчёт аудита — Amnezia Web Panel
Аудит проведён по пяти направлениям параллельно. Ниже — консолидированный результат, сгруппированный по критичности и домену. Всего найдено 60+ проблем: 12 критических, 28 высокого приоритета, 20+ среднего.

🔴 КРИТИЧЕСКИЕ (P0) — неработающий код / уязвимости удалённого выполнения
1. Telegram-бот: ВСЕ SSH-операции проваливаются из-за нерасшифрованных кредов
Файл: telegram_bot.py:426-432, _get_ssh_and_manager
_build_data_dict сохраняет Fernet-зашифрованные s.password / s.private_key (формат v1:<token>). _get_ssh_and_manager передаёт их в SSHManager без дешифровки → SSH-подключение к серверам всегда падает. Затронуты: выдача конфигов, QR-коды, управление клиентами, установка протоколов.

Fix: Использовать app.get_ssh(server), который вызывает decrypt_secret().

2. Telegram-бот: ВСЕ DB-записи молча не работают
Файл: telegram_bot.py:881, 938, 959, 987, 1177, 1234, 1382, 1445
Повсеместно вызывается синхронный db.commit() на AsyncSession — либо падает с MissingGreenlet, либо возвращает корутину, которая отбрасывается. Ни одно изменение (добавление/удаление пользователя, сервера, клиента) не сохраняется в БД. Плюс мутации делаются над in-memory dict, а не ORM-объектами.

Fix: Заменить все мутации на работу с ORM через репозитории + await db.commit().

3. Telegram-бот: /addserver крашится с AttributeError
Файл: telegram_bot.py:870-871
_build_data_dict возвращает data["servers"] как dict, а команда делает data.setdefault("servers", []).append(...) — dict не имеет .append(). Плюс пароль сохраняется в открытом виде (без Fernet) в Telegram-чате.

Fix: Переписать на ORM (models.Server), шифровать пароль через encrypt_secret().

4. Telegram-бот: _admin_delete_user разрушает структуру данных
Файл: telegram_bot.py:986-987
Конвертирует data["users"] из dict в list, ломая весь последующий код.

Fix: Переписать на ORM.

5. API: perform_delete_user / perform_toggle_user — разбитые эндпоинты
Файл: app.py:1159-1206 (функции) + routers/users.py:259,274 (вызовы)
Сигнатура функций: data: dict. Вызываются с AsyncSession как первым аргументом → TypeError при обращении data['users']. Удаление и блокировка пользователя через веб-интерфейс не работают.

Fix: Переписать на ORM, либо маршрутизировать одиночные операции через perform_mass_operations.

6. API: api_add_user / api_delete_user / api_toggle_user — обход Bearer-токенов
Файл: routers/users.py:122, 252, 270
Используют get_current_user(db, request) (только сессионная кука) вместо _check_admin (сессия + Bearer). API-токены игнорируются — администратор с токеном не может управлять пользователями.

Fix: Заменить на await app_module._check_admin(db, request).

7. Command Injection в Telemt API curl
Файл: managers/telemt_manager.py:56-57

js_data = json.dumps(data).replace('"', '\\"')
cmd += f" -H 'Content-Type: application/json' -d \"{js_data}\""
Экранирование ломаное — backticks, $(), переводы строк не защищены. user_ad_tag приходит из пользовательского ввода и попадает в JSON → shell injection.

Fix: shlex.quote(js_data) или запись JSON во временный файл и -d @/tmp/payload.json.

8. Command Injection в Docker-командах — порты не приводятся к int
Файлы: managers/wireguard_manager.py:207, awg_manager.py:422, xray_manager.py:336, telemt_manager.py:200
Порты интерполируются напрямую в shell-команды без int(). Если роутер пропустит нечисловое значение, возможна инъекция.

Fix: Добавить port = int(port or <default>) в начале методов install_protocol.

9. Open Redirect через /set_lang/{lang}
Файл: routers/templates.py:21-26
Редирект на request.headers.get("referer", "/") без валидации. Referer: https://evil.com → пользователь перенаправляется на фишинговый сайт.

Fix: Валидировать Referer против списка доверенных URL панели.

10-12. (Латентные) Инъекции в WireGuard/AWG peer section echo + неэкранированные аргументы docker exec
Файлы: wireguard_manager.py:604-606, awg_manager.py:1016-1018
Экранируются только одинарные кавычки; double-quotes, backticks, $() — нет. Пока peer-секции генерируются кодом, но при добавлении пользовательских полей станет активной уязвимостью.

Fix: Записывать конфиг через docker cp из временного файла, а не через echo в shell.

Аудит завершён. Ключевой вывод: Telegram-бот сломан практически полностью — ни одна операция записи в БД не работает (синхронный commit() на AsyncSession), а SSH-подключения падают из-за нерасшифрованных кредов. Плюс в веб-панели разбиты эндпоинты удаления/блокировки пользователей и обход Bearer-аутентификации в трёх роутах. В SSH-менеджерах — реальная command injection через Telemt API.

Рекомендую начать с Telegram-бота (перевод на ORM + await + app.get_ssh()) и параллельно закрыть критические дыры в API и менеджерах. После этого — hardening безопасности (сессии, KDF, индексы).
